# DECISIONS.md — Architecture Decision Records (ADR)

> Log of significant decisions made during the project.
> Each entry answers: What was decided, why, and what was rejected.

---

## ADR-001 — Out-of-tree drivers, not in-tree modifications

**Decision:** All custom drivers live in `drivers/` as out-of-tree modules.
**Why:** `kernel/` is a read-only git submodule (RPi fork). Modifying it breaks `git submodule update`.
**Rejected:** Forking the kernel with patches — maintenance burden on kernel upgrades.

## ADR-002 — Buildroot for root filesystem, not Yocto

**Decision:** Use Buildroot with `BR2_EXTERNAL` for the root filesystem.
**Why:** Simpler, faster builds, sufficient for this project's scope. `BR2_EXTERNAL` keeps custom config separate.
**Rejected:** Yocto/OpenEmbedded — heavier, steeper learning curve, overkill for single-board target.

## ADR-003 — Device Tree overlays, not hardcoded pin assignments

**Decision:** GPIO pins, I2C addresses, and IRQ lines are defined in DTS overlays.
**Why:** Allows reconfiguration without recompiling drivers.
**Rejected:** `module_param()` for all pin assignments — less standard, no DT binding documentation.
**Exception:** `gpio-rust` uses `module_param gpio_pin` in addition to DTS because Rust gpiod bindings don't exist in 6.12.

## ADR-004 — gpiod descriptor API, not legacy integer API

**Decision:** All GPIO operations use `gpiod_*` functions exclusively.
**Why:** Legacy API (`gpio_request`, `gpio_set_value`) deprecated since kernel 4.x. Descriptor API handles polarity, active-low, etc. correctly.
**Rejected:** Legacy API — deprecated, no polarity support, no DT integration.
**Bridge:** `gpio-rust` uses `gpio_to_desc()` to convert integer GPIO numbers to descriptors (Rust FFI limitation).

## ADR-005 — Hermetic Docker build environment

**Decision:** All build targets run inside a Docker container via `$(RUN)` wrapper.
**Why:** Reproducible builds — same toolchain, same Rust version, same host dependencies on any machine.
**Rejected:** Bare-metal builds — toolchain/version mismatches between developers.

## ADR-006 — mk/docker.mk wrapper pattern

**Decision:** `DOCKER_RUN_NO_TTY` and `DOCKER_RUN_TTY` defined in `mk/docker.mk`. `$(RUN)` prefix on every build command.
**Why:** Single place to change Docker config. `IN_DOCKER` detection avoids double-wrapping inside container.
**Rejected:** Separate `docker-compose.yml` — more complex, doesn't integrate as cleanly with Make.

## ADR-007 — kernel-prepare as CI alternative to full Buildroot

**Decision:** `make kernel-prepare` configures `kernel/` directly for CI builds without running full Buildroot.
**Why:** Full Buildroot takes ~60 min. CI only needs kernel headers + `.config` for module compilation. `kernel-prepare` takes ~2-3 min.
**Steps:** `bcm2711_defconfig` → `scripts/config --disable MODVERSIONS --enable RUST` → `olddefconfig` → `modules_prepare`.

## ADR-008 — CI builds Docker image locally, not pull

**Decision:** `ci.yml` always runs `docker build` — never `docker pull`.
**Why:** On fresh repo/runner, the image may not exist on `ghcr.io` yet. `docker-publish.yml` publishes it, but CI must work independently.
**Rejected:** Always pull from registry — fails if image not yet published.
**Used in release:** `release.yml` does pull from ghcr.io (assumes image exists after at least one `docker-publish.yml` run).

## ADR-009 — checkpatch excludes userspace and common

**Decision:** `checkpatch.pl` only runs on `drivers/*/src/*.c` and `drivers/*/include/*.h`. Excludes `*/userspace/*`, `*/common/*`, `*.mod.c`.
**Why:** Userspace code follows different conventions (POSIX C, `uint8_t` instead of `u8`, `typedef struct` allowed). Common library is userspace code.

## ADR-010 — SDK base image separated from builder image

**Decision:** Two Docker images: `sdk.Dockerfile` (base, toolchain only) and `Dockerfile` (full builder, adds Rust + host deps).
**Why:** SDK image changes rarely (only when toolchain updates). Builder image can be rebuilt quickly using SDK as cache layer.
**Images:** `ghcr.io/nhat092005/build-os-sdk:gcc14.3-glibc` (base), `build-os-builder` (full).

## ADR-011 — release.yml uses make buildroot + make build, not build-all

**Decision:** Release runs `make buildroot` then `make build` as separate steps.
**Why:** `make build-all` = `make buildroot` + `make build` — would cause double Buildroot if any caching is involved. Separate steps give clearer CI logs.

## ADR-012 — libuart-transport as shared library

**Decision:** ESP32 and STM32 UART tools share `drivers/common/libuart-transport/` for framing protocol.
**Why:** Both use identical UART framing (SOF + CMD + LEN + SEQ + PAYLOAD + CRC16). Code reuse avoids duplication.
**Constraint:** Must be cross-compiled with correct `CC` — stale host `.o` files cause ELF class mismatch.

## ADR-013 — CHANGELOG.md auto-generated by git-cliff

**Decision:** `CHANGELOG.md` generated by `git-cliff` using conventional commits.
**Config:** `cliff.toml` at repo root.
**Why:** Manual changelog maintenance is error-prone. Conventional commits provide structured data for automated generation.
